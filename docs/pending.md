## 原工作流明确延期的模块

- **私信（private_message）**：15 个方法依赖 Android 私信会话，包含发送/删除消息；原工作流未设计会话模型。此轮没有扩展或测试私信。
- **COS 上传（helper/init_upload、finish_upload、helper_utils）**：需要分块、重试、上传状态及对象存储流程，原工作流未纳入此能力。
- **手机客户端 MQTT 扫码**：需长连接与事件流，原工作流明确延期；本轮所有登录测试均按用户要求排除。

- 微信/QQ 扫码、手机验证码、凭据刷新：两轮用户均明确排除；NeuMusic 侧保持现有 WebView 登录，未新增或测试扫码流程。
- **全量清空不喜欢歌曲**：现有账号包含原始条目。仅验证 Token 预检及离线参数/失败保护，不删除既有条目，避免改变原始时间与顺序。增删单个临时不喜欢条目已完整往返。

## 2026-10-05 接入引入的新边界

- **FFI 0.2.0 成套更新**：模型加了字段，Rust 侧按字段顺序编码；Swift/Kotlin bindings、JNI 库与 native library 必须由同一版本生成打包，旧 0.1 bindings 不能配 0.2.0 native。现有 macOS 安装仍是 0.1 产物，接入新组件前要先成套更新。
- **电台轮播无状态**：`fetch_radio_track_batch` 每批 `total` 固定为 `null`，跨批去重、`firstPlay=false` 续拉与结束判断都由宿主负责；组件不保存轮播状态。
- **喜欢写回执语义**：`set_liked_by_id` 区分成功与限流（`code=1000` → `throttled`），旧 `set_liked` 回执形状不变；宿主按 `success` 决定重试，组件不自动重试。

## 已保留的接口约定

- 同端点的参考别名继续复用既有入口，不另增重复方法（like/unlike→set_liked，推荐流/新歌等）。
- 参数缺省及平台档案保持参考/既有实测结论；调用方可显式指定 `platform`。分页接口返回单页及续页元数据，宿主负责自动收集。
- 模型统一 camelCase；任意 JSON 对象在 FFI 中为 JSON 文本，子进程仍为真实对象/数组。
- 加密音质返回空 `ekey`/`purl` 时保留授权信息，不自动替宿主决定降级策略。
- 子进程 `id` 是关联 ID，资源 ID 位于 `resultId`；FFI 的资源模型 `id` 不改名。
